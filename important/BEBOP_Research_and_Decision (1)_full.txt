1. Thesis and problem
Thesis. BEBOP should be a fail-closed verifier: it approves a physical action only when each assumption behind it is backed by measured
evidence, and otherwise returns UNDECIDED together with the specific missing measurement. Problem. Perception-driven systems keep
acting on stale or low-quality state without knowing it. The evidence below shows this is real, but it is a family of problems (degraded
sensing, stale state, VLM grounding errors, failed actions), not one universal problem.

What is genuinely new? Not the pipeline: change detection, diagnosis, VLM-guided extra observation and replanning already exist in
VAP-TAMP. Red-team result: a team that built VAP-TAMP could argue that its paraphrase-vote check, view-sufficiency check and
re-verification of preconditions before every action already cover BEBOP's loop, and that re-verifying before acting makes explicit
dependency tracing largely redundant. I accept that for the ledger, so it is now an explanation aid, not a novelty claim. What I found in the
paper (code not audited) is that its Algorithm 2 still returns a binary value when the viewpoint budget runs out, so it has no abstain output,
and its checks are VLM yes/no rather than metric. The defensible gap is therefore narrow: a verifier that abstains with a quantified
margin, tested head-to-head on scenes where the evidence is genuinely insufficient. If a VAP-style baseline matches it on false
approvals, the contribution shrinks to engineering and should be reported that way.
Verdict on the problem: real, important, and worth solving in narrow form. Original BEBOP is not differentiated enough to build as
specified. First users: robotics/CV engineers who need an audit trail for 'why did the system say go?'. Today they use ad-hoc thresholds and
logs.

4. Recommended solution: BEBOP-Gate (tabletop clearance verifier)
Workflow. (1) SAM 3.1 segments the moving object, obstacles and passage edges from a short clip. (2) Deterministic code measures the
gap and its uncertainty (spread across 3 frames x 5 prompt variants, plus a printed scale marker). (3) Each assumption (for example gap at
least object width + margin) is written to a versioned ledger with the mask evidence that supports it. (4) New frames re-score every
assumption; if an input changed, the assumption and every decision that depends on it are marked invalid. (5) Verdict: PASS only if margin
exceeds 2 sigma; FAIL if the violation exceeds 2 sigma; otherwise UNDECIDED plus the missing measurement (which dimension, which
tolerance, which unoccluded view). (6) If FAIL, check an alternate route with the same verifier.

5. Evaluation (build this; report only what you measure)
Data: about 40 phone-captured scenes: 3 gap classes (clear pass, marginal, clear fail) x clean, hand-occluded, blur, low light, lookalike
distractor, object moved mid-clip. At least 10 are unanswerable by design (the deciding edge is hidden or the gap is within measurement
error), so the correct output is UNDECIDED. Ground truth: ruler/caliper gap. Baseline 1: Muse Spark yes/no on the image. Baseline 2:
SAM mask + geometry, single shot, binary. Baseline 3 (new): a VAP-style verifier I reimplement from the paper's description on Muse Spark
(5 paraphrased questions, majority vote, sufficiency check, forced binary answer at budget exhaustion); label it a reimplementation, not their
code. Metrics, in priority order: false-approval rate on all scenes and on the unanswerable subset; risk-coverage curve (errors vs fraction
answered); stale-plan retention after a change; missed changes; UNDECIDED cases resolved by one extra measurement. Target, not
result: fewer false approvals than all three baselines at at least 70% coverage.
